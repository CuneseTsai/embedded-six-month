## 四、观察结果与证据

### 1. `-O0` 汇编

观察到以下指令：

```asm
movl    $30, -4(%rbp)
movl    $40, -8(%rbp)
movl    -8(%rbp), %edx
movl    -4(%rbp), %eax
movl    %eax, %ecx
call    add
movl    %eax, -12(%rbp)
movl    -12(%rbp), %edx
call    printf
```

在这次编译结果中，局部变量通过相对于 `%rbp` 的地址访问，`add` 被调用，返回值随后保存并用于调用 `printf`。

### 2. `-O2` 汇编

观察到：

```asm
movl    $70, %edx
leaq    .LC0(%rip), %rcx
call    printf
```

`add` 调用及其对应的局部变量读写不再出现。编译器利用已知的输入值计算出结果 70，并直接准备 `printf` 的参数。

在本次 x86-64 Windows ABI 环境下，`%edx` 用于传递这里的整数参数 70，`%rcx` 保存格式字符串地址。不能将 70 解释为被直接写入栈内存。

汇编仍有栈空间调整指令；这些指令不能证明原先的局部变量仍以相同方式存放在栈上。

上述观察只适用于本次源码、GCC 版本、目标平台和编译选项，不应推广为所有工具链必然产生相同汇编。

## 五、原理分析

1. 编译器可以利用编译期已知的值执行常量传播和常量折叠。
2. 优化后的机器代码不必为每个源代码局部变量保留独立的栈内存位置。
3. 如果函数调用对程序可观察行为没有额外影响，编译器可能消除调用并直接使用计算结果。
4. `.data`、`.bss` 等是常见目标文件或映像中的段；栈和堆是运行时内存管理区域。不同概念有关联，但不能混为一谈。
5. 变量的作用域、链接属性、存储期和最终机器地址属于不同层次，需要分别分析。
